# Add Observability Skill

## Logging (Spring Boot — SLF4J + Logback)

### What to Log
- **Every incoming request**: method, path, authenticated user email (from SecurityContext), response status, duration in ms
- **Every Groq API call**: model used, endpoint, duration in ms, response status (not the full response body)
- **Groq failures**: full exception message + status code + response body (truncated to 500 chars)
- **Auth events**: login success (email), login failure (email, reason), token generation, OAuth2 success
- **Score results**: question number, difficulty, score (0-10), duration of evaluation — useful for interview analytics
- **Lightcast token refresh**: "Refreshing Lightcast OAuth2 token" — lets you monitor token churn

### What NOT to Log
- `audioData` base64 field — megabytes of binary data per request, useless in logs
- JWT tokens — logging them is equivalent to logging passwords
- Passwords — never, even hashed
- Full Groq prompts if they contain user-submitted content (PII risk)
- Full request bodies containing audio

### Structured Log Format
Use MDC (Mapped Diagnostic Context) to add request-scoped fields:
```java
// In a request filter or interceptor
MDC.put("userId", email);
MDC.put("requestId", UUID.randomUUID().toString());
// SLF4J will include these in every log line for this thread
```

Target log format (JSON for production, readable for dev):
```json
{
  "timestamp": "2025-01-15T14:23:01.123Z",
  "level": "INFO",
  "logger": "com.app.demo.service.InterviewService",
  "message": "Groq Whisper transcription complete",
  "userId": "user@example.com",
  "requestId": "abc-123",
  "durationMs": 1847,
  "audioSizeBytes": 45231
}
```

Add to `application.properties`:
```properties
logging.pattern.console=%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} [%X{requestId}] - %msg%n
```

### Log Levels by Category
- `log.info()` — normal request/response, auth success, Groq call start/complete
- `log.warn()` — Groq response required fallback parsing, token approaching expiry
- `log.error(message, e)` — Groq API failure, DB error, JWT validation failure
- `log.debug()` — prompt content (dev only), cached token hit/miss

## Metrics (Spring Boot Actuator + Micrometer)

Add to `build.gradle`:
```groovy
implementation 'org.springframework.boot:spring-boot-starter-actuator'
implementation 'io.micrometer:micrometer-registry-prometheus'
```

Add to `application.properties`:
```properties
management.endpoints.web.exposure.include=health,info,prometheus,metrics
management.endpoint.prometheus.enabled=true
management.metrics.export.prometheus.enabled=true
```

### Four Golden Signals for This Project

**1 — Latency (histogram)**
```java
// Wrap each Groq call
Timer.Sample sample = Timer.start(meterRegistry);
// ... call Groq ...
sample.stop(Timer.builder("groq.api.latency")
    .tag("endpoint", "transcriptions")
    .tag("model", "whisper-large-v3-turbo")
    .register(meterRegistry));
```

**2 — Traffic (counter)**
```java
Counter.builder("interview.answers.submitted")
    .tag("outcome", "success") // or "error"
    .register(meterRegistry)
    .increment();
```

**3 — Errors (counter)**
```java
Counter.builder("groq.api.errors")
    .tag("status", String.valueOf(e.getStatusCode().value()))
    .register(meterRegistry)
    .increment();
```

**4 — Saturation (gauge)**
```java
// Monitor HikariCP connection pool usage
// Spring Boot Actuator + HikariCP expose this automatically at:
// /actuator/metrics/hikaricp.connections.active
```

## Distributed Tracing (OpenTelemetry)

Add to `build.gradle`:
```groovy
implementation 'io.opentelemetry.instrumentation:opentelemetry-spring-boot-starter:2.5.0'
```

Add to `application.properties`:
```properties
otel.service.name=interview-backend
otel.exporter.otlp.endpoint=http://localhost:4317
otel.traces.exporter=otlp
```

### Span Naming Convention
- HTTP spans: `HTTP POST /api/interview/answer` (auto-generated by Spring instrumentation)
- Groq calls: `groq.whisper.transcribe`, `groq.llama.score`, `groq.llama.adaptive-question`
- DB queries: auto-generated by Hibernate instrumentation

### Required Span Attributes
```java
Span.current()
    .setAttribute("interview.question_number", questionNumber)
    .setAttribute("interview.difficulty", difficulty)
    .setAttribute("groq.model", groqModel)
    .setAttribute("audio.size_bytes", audioBytes.length);
```

### Propagation Headers
Ensure `W3C TraceContext` headers (`traceparent`, `tracestate`) are passed through to Groq calls — configure `RestTemplate` with an OpenTelemetry-aware interceptor.
